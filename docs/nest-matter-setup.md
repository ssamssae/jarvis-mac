# Google Nest에 자비스 연결하기: Matter 등록부터 첫 호출까지

v1.2.0 기준. 이 구성은 **개발자용 테스트 Matter 어댑터**입니다. 인증된 완제품을 Google Home에 추가하는 것과 달리 개발자 콘솔의 테스트 등록이 필요합니다. 음성 입력은 **시작만 네스트**, 프로그램·컴퓨터 선택과 본문은 **자비스가 실행 중인 Mac 마이크**가 받습니다.

## 준비물과 먼저 확인할 것

- README에 따라 설치한 자비스, 마이크 권한, whisper.cpp와 음성 모델, 동작하는 Nest 음성 출력.
- Node.js 22 이상, npm, `/opt/homebrew/bin/python3`에서 실행되는 Python. 어댑터의 실행 경로는 현재 Apple Silicon Homebrew 구성을 기준으로 합니다.
- 같은 홈·로컬 네트워크의 휴대폰 Google Home 앱, Matter 제어를 지원하는 홈 허브, 일본어 호출을 처리하도록 설정된 Google Assistant/Nest. 네스트 스피커의 음성 기능과 Matter 허브 지원 여부는 별개이므로 실제 보유 모델을 확인하세요.
- Google Home의 홈을 관리하는 Google 계정. 개발자 콘솔에도 같은 계정을 사용합니다.
- 작업 시작·종료의 개인 기기 설정과 [세션 입력 대상 설정](voice-session-input.md). Matter 연결만으로 대상 세션이나 기기 목록이 만들어지지는 않습니다.

먼저 Mac에서 **“자비스, 보이스 스타토”**로 “어디로 연결할까요?”가 나오는지 확인합니다. 로컬 입력부터 안 되면 Google Home 등록과 별개로 마이크·모델·세션 설정을 확인하세요.

## 1. Matter 어댑터 실행

자비스 소스 폴더에서 다음을 실행합니다. 네이티브 앱 설치와 별개인 선택 기능입니다.

```sh
cd scripts/google-home
npm ci --ignore-scripts --no-audit --no-fund
node server.mjs
```

처음에는 이 터미널을 열어둔 채 설정합니다. 이 프로세스가 끝나거나 Mac이 잠들면 제어가 끊길 수 있습니다. 상시 사용 시 운영 환경에 맞게 로그인 서비스로 관리하되, 이미 설치된 서비스와 두 번 실행하지 마세요.

어댑터는 두 개의 가상 플러그를 제공합니다. 실제 콘센트를 구매해야 한다는 뜻이 아니라, Google Home이 이해하는 플러그의 ON/OFF를 자비스 동작으로 연결한다는 뜻입니다.

| Google Home에서 구분할 이름 | 역할 | 기본 통신 포트 |
|---|---|---|
| Jarvis Work Start — 등록 후 Jarvis Work로 이름을 바꿔도 됨 | ON: 작업 시작 / 명시적 OFF: 종료 확인 질문 | UDP 5540 |
| Jarvis Voice Input | ON: 음성 입력 선택 시작 / OFF: 동작 없음 | UDP 5541 |

개인 상태는 기본적으로 `~/Library/Application Support/JarvisGoogleHome`에 보관합니다. `status.json`의 `online`, `voice_online`은 각 기기의 실행 상태이고, `commissioned`, `voice_commissioned`는 페어링 여부입니다. `true`만으로 Google Home에서 실제 제어가 된다고 단정하지 않습니다.

## 2. Google Home 개발자 테스트 등록

1. [Google Home Developer Console](https://console.home.google.com/)에 홈을 관리하는 계정으로 로그인합니다.
2. 프로젝트를 만들거나 기존 자비스용 프로젝트를 엽니다. 필요한 약관은 직접 확인합니다.
3. Matter 통합을 추가하고 기기 종류를 플러그/On-Off Plug-in Unit에 맞춥니다.
4. 테스트 Vendor ID를 **`0xFFF1`**, Product ID를 **`0x8000`**으로 설정하고 저장합니다. 현재 `server.mjs`가 사용하는 값과 같아야 합니다.
5. 같은 VID/PID의 통합이 이미 있다면 기존 설정을 확인합니다. 음성 입력용이라고 같은 조합의 통합을 무조건 하나 더 만드는 것이 아닙니다. 작업용과 음성 입력용은 홈 앱에서 각각 페어링할 별개의 기기입니다.

테스트 VID와 펌웨어 PID의 일치, 개발용 통합의 필요 조건은 [Google의 통합 생성 안내](https://developers.home.google.com/matter/integration/create)와 [Matter 시작 안내](https://developers.home.google.com/matter/get-started)를 기준으로 합니다. 화면 명칭과 지원 기기는 앱·허브 버전에 따라 달라질 수 있습니다.

## 3. 모바일 Google Home에서 두 기기를 각각 페어링

Google Home의 기기 추가에서 Matter 기기를 선택합니다. QR을 표시하는 별도 로컬 도구가 있다면 스캔할 수 있지만, 이 패키지의 기본 실행기는 페어링 정보를 JSON으로 저장합니다. **QR 화면 없이 수동 코드로도 등록할 수 있습니다.**

| 등록할 기기 | 개인 코드 파일 |
|---|---|
| 작업용 | `pairing.json` |
| 음성 입력용 | `voice-pairing.json` |

각 파일의 `manualPairingCode`가 수동 코드입니다. `qrPairingCode`의 `MT:...` 문자열을 수동 숫자 코드란에 넣지 마세요. 먼저 작업용 코드를 Mac 클립보드에 복사하는 예입니다. 아래 명령은 코드 값을 터미널 출력에 남기지 않습니다.

```sh
python3 - <<'PY' | pbcopy
import json
from pathlib import Path
p = Path.home() / 'Library/Application Support/JarvisGoogleHome/pairing.json'
print(json.loads(p.read_text())['manualPairingCode'], end='')
PY
```

1. 모바일 Google Home에서 QR 대신 코드를 입력하는 항목을 선택합니다.
2. 방금 복사한 작업용 수동 코드를 입력합니다. 휴대폰으로 안전하게 옮기는 방법은 본인 환경을 사용합니다.
3. 원하는 홈과 방을 지정하고 이름을 **Jarvis Work**처럼 알아보기 쉽게 정합니다.
4. 위 명령의 파일명을 **`voice-pairing.json`**으로 바꿔 음성 입력용 기기를 따로 등록합니다. 이름은 **Jarvis Voice Input**으로 구분합니다.
5. 앱에 두 기기가 모두 나타나는지, 오프라인은 아닌지 확인합니다. 기존 작업용 페어링 파일이나 Matter 저장소를 지워 두 번째 기기를 등록하려고 하지 마세요.

코드·QR·Matter 저장소는 개인 자격정보입니다. 공개 이슈, 저장소, 스크린샷에 올리지 마세요. 기기를 삭제하고 다시 등록할 때도 기존 상태와 다른 컨트롤러 연결부터 확인합니다. [공식 페어링 안내](https://developers.home.google.com/matter/integration/pair).

## 4. 루틴 3개 만들기

Google Home 자동화/루틴에서 음성 시작 조건과 기기 제어를 연결합니다. 실제 편집기에 나타나는 **방과 기기**를 선택하세요. 아래 이름은 권장 이름이며 기기 식별자를 문자열로 추측해서 쓰지 않습니다.

| 루틴 | 일본어 시작 조건 | 발음 | 기기 제어 |
|---|---|---|---|
| 음성 입력 | `ボイススタート` | 보이스 스타토 | Jarvis Voice Input **켜기** |
| 작업 시작 | `しごとスタート` / `仕事スタート` | 시고토 스타토 | Jarvis Work **켜기** |
| 작업 종료 | `しごとおわり` / `仕事終わり` | 시고토 오와리 | Jarvis Work **끄기** |

각 루틴을 저장하고 활성화합니다. 등록했던 “메모 스타토”는 다른 내장 기능의 응답으로 이어진 사례가 있어, 이번 버전 안내는 **보이스 스타토**로 통일했습니다.

작업용 플러그는 시작 요청 후 스스로 OFF로 돌아옵니다. 이 **자동 초기화는 종료 요청이 아닙니다.** 종료 루틴은 현재 화면에 OFF로 보여도 명시적인 끄기 명령을 보내야 합니다. 음성 입력 루틴을 작업용 기기에 연결하면 받아쓰기 대신 작업 시작이 실행되므로 기기 선택을 다시 확인하세요.

## 5. 실제로 시험하기

### 음성 입력

“오케이 구글, 보이스 스타토” → “어디로 연결할까요?” → “코덱스” → “어떤 노드인가요?” → 설정한 컴퓨터 이름 → “말씀하세요” → 짧은 본문 → “엔터”.

프로그램 선택 이후에도 네스트에 계속 말하는 구조가 아닙니다. Mac 마이크가 들을 수 있는 거리에서 답합니다. 자비스를 직접 호출할 때는 **“자비스, 보이스 스타토”**입니다. 기존 “음성 입력”은 호환용으로 지원합니다.

수신한 세션의 본문과 답변을 먼저 확인합니다. 지원 브릿지의 출처 카드까지 구성했다면 ‘네스트로 시작 · [마이크 기기] 음성 입력 · 자비스 전달’도 확인합니다. 카드가 없다는 이유만으로 본문을 반복 전송하지 마세요.

### 작업 시작·종료

시작 루틴은 설정한 밝기·WOL 등의 요청을 보낼 수 있으므로 의도한 대상인지 먼저 확인합니다.

“오케이 구글, 시고토 오와리” → **“오늘의 작전을 종료할까요?”**를 끝까지 듣기 → 질문 재생 후 **12초 안에 Mac 마이크로 “하이(`はい`)”** → 기존 종료 스크립트 실행.

다른 답변, 시간 초과, 질문 전 발화, 반복 응답은 종료 승인이 아닙니다. 실제 기기 종료가 포함될 수 있으므로 작업을 저장한 뒤 시험합니다. WOL 송신/종료 요청 기록과 실제 전원 상태는 따로 확인합니다.

## 호출이 안 될 때

| 관측 | 먼저 확인할 것 |
|---|---|
| 기기가 발견되지 않음 | 어댑터 실행, 같은 홈/네트워크, 허브 지원, 개발자 계정 및 VID/PID 일치, 해당 기기의 코드 |
| 페어링은 됐는데 오프라인 | Mac 절전, Node 프로세스 종료, 로컬 네트워크 차단·게스트망·VPN |
| 네스트가 메모 등 다른 기능으로 답함 | 루틴 활성화·일본어 시작 조건·Assistant 언어, 보이스 스타토 등록 여부 |
| 앱에서 실행되는데 음성 호출만 안 됨 | 기기 연결보다 음성 시작 조건을 먼저 확인 |
| 질문 뒤 프로그램/컴퓨터를 못 알아들음 | 실제 수신은 Mac 마이크인지, 마이크 권한·음성 모델, 설정한 별칭 |
| 입력이 안 된 것처럼 보임 | `last-dictation.json` 상태, 실제 대상 세션 본문, 텔레그램 카드 순서로 대조 |
| 종료 질문 뒤 하이가 안 먹음 | 질문 재생 완료, 12초 제한, Mac 마이크 거리; 종료 명령을 무작정 반복하지 않기 |

현장 확인은 일부 구성의 실제 호출 성공입니다. 모든 허브·언어·프로그램 조합의 호환성이나 인식률을 보장하지 않습니다.

## 앱 작업 명령 확인 경로 (T-260926-007)

Google Home 호출어는 기존 시고토 스타토/시고토 오와리 그대로 유지합니다.
Mac 앱은 기존 호출명 “자비스” 뒤에 “시고토 스타토” 또는 “시고토 오와리”를 말합니다.
“자비스”를 먼저 불러 응답을 들은 뒤 명령만 말하는 방식도 같습니다.
시작은 기존 work_mode 경로, 종료는 기존 확인 질문 경로로 진입합니다.
앱 종료는 질문 후 12초 안에 새 “예/네”, Google 경유는 기존 “はい” 확인을 유지합니다.
검증: 새 문구의 정확 일치 및 기존 한국어 문구의 비일치, 호출 후 라우팅,
확인 전 실행 금지, 중복 승인/시간 초과 방어를 모의 실행 검사로 확인합니다.
실제 발화 인식과 기기 동작은 이 검사와 별개이며 사용자 음성 확인 전에는 미확인입니다.
